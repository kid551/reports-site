reports-site

一个托管在 GitHub Pages 上的极简报告归档站。把任意完整的 HTML 文件放进 posts/，git push 后自动渲染到列表里，原样式 100% 保留。

Astro GitHub Pages FlexSearch Tailwind

核心理念

  • 你的 HTML 即真相：详情页直接打开你扔进 posts/ 的原文件，构建时只在 </body> 前注入一个浮动的「← 返回列表」按钮，不改你的样式、不改你的结构。
  • 零元数据维护：标题、描述、日期、分类、关键词，全部从 HTML 的 <title> / <meta> / 文件名 / 目录名自动提取。
  • 本地一键发布：pnpm deploy 交互确认后 commit + push，GitHub Actions 自动构建并发布，无需登录服务器。

快速开始

# 1. 安装依赖（首次）
pnpm install

# 2. 本地预览
pnpm dev
#    → http://localhost:4321/reports-site/

# 3. 新增一篇文章（可选）
pnpm new "我的报告标题"
#    → 生成 posts/YYYY-MM-DD-我的报告标题.html 骨架

# 4. 编辑元数据（可视化，仅本地）
pnpm admin
#    → http://127.0.0.1:4322/  改 title/description/date/category/keywords

# 5. 本地构建预览
pnpm build && pnpm preview

# 6. 一键发布
pnpm deploy

机制原理

1. 构建流程

每次执行 pnpm dev 或 pnpm build，Astro 的 predev / prebuild 钩子都会先跑 scripts/build-posts.ts。这个脚本完成三件事：

  1. 用 linkedom 解析 posts/ 下每一个 *.html，抽出标题、描述、纯文本正文等。
  2. 把原 HTML 原样复制到 public/posts/，只在 </body> 前插入一个固定定位的浮动返回按钮（用 inline style，避免和你的 CSS 冲突）。
  3. 输出两个工件：
    • .generated/posts.json ← 给 Astro 首页在构建时读，渲染成列表。
    • public/search-index.json ← 浏览器端 FlexSearch 在用户聚焦搜索框时按需下载。

2. 元数据提取规则

字段提取来源（按优先级）
title<title> → <h1> → 文件名
description<meta name="description"> → 首个非空 <p>（截断 200 字）
date文件名前缀 YYYY-MM-DD- 或 YYYYMMDD- → 文件 mtime
category所在子目录名（直接位于 posts/ 下则归入 未分类）
keywords<meta name="keywords">（逗号分隔）

3. 搜索

客户端用 FlexSearch 的 Document 索引，对 title / description / keywords / body 四个字段做前缀分词。索引文件懒加载，搜索匹配片段会在结果里高亮。正文为节省体积截断在 20000 字符（可改 scripts/build-posts.ts 顶部的 MAX_BODY_CHARS）。

4. 部署

workflow .github/workflows/deploy.yml 监听 main 的 push，跑 pnpm build 后通过 actions/deploy-pages 发布到 GitHub Pages 的原生通道（不需要 gh-pages 分支）。

微妙处的考虑

  • 样式 100% 隔离 vs 用户体验：考虑过用 iframe 隔离，但 iframe 会破坏滚动行为、键盘焦点和外链锚点。最终选择直接打开原 HTML（不同页面 = 天然隔离），构建时只注入一个 z-index: 2147483647 的浮动按钮回到列表。inline style 避免与原文档样式冲突。
  • 搜索索引不打进 JS bundle：把 search-index.json 放在 public/ 而不是 import 进客户端 bundle。这样首页打开很快，索引按需 fetch。
  • posts/ 是源、public/posts/ 是产物：public/posts/ 和 search-index.json 都在 .gitignore 里，由 build 现成产出，不进 git 历史。
  • 预构建钩子：用 npm 的 predev / prebuild 钩子串联，而不是写 Astro 插件，避免引入额外抽象。
  • 提交前确认：pnpm deploy 默认会列出 diff 让你按 y 才提交，避免误推；CI/批处理场景可加 -y 跳过。

使用方法

添加一篇文章（手写）

直接把任意 HTML 文件放进 posts/。命名建议带日期前缀，例如：

posts/2026-05-22-q2-review.html
posts/research/2026-05-22-llm-eval.html   # 子目录 = 分类

添加一篇文章（用脚手架）

pnpm new "Q2 复盘"
#  → posts/2026-05-22-q2-复盘.html

pnpm new "LLM 评测" --category research
#  → posts/research/2026-05-22-llm-评测.html

编辑元数据（仅本地，不需要服务器）

pnpm admin 启动一个绑定在 127.0.0.1:4322 的本地服务，浏览器打开 http://127.0.0.1:4322/ 即可可视化编辑每篇文章的元数据：

  • title / description / keywords：直接重写原 HTML 文件的 <title> 和 <meta>，不改正文。
  • date：改动后自动按 YYYY-MM-DD-slug.html 规则重命名文件。
  • category：改动后自动把文件移动到对应子目录（未分类 = 放回 posts/ 根目录）。
  • 支持删除文章。

为什么只有你能用：服务仅监听 127.0.0.1（loopback），网络上其他设备无法访问；同时校验 Host / Origin 请求头，挡住 DNS rebinding 类攻击。你的另一台电脑、手机、同事，都进不来。

编辑完后照常 pnpm deploy 发布。

发布

pnpm deploy             # 默认会列出变更，输入 y 确认后提交并 push
pnpm deploy -y          # 跳过确认（脚本里用）
pnpm deploy -m "msg"    # 自定义 commit 信息

首次设置 GitHub Pages

  1. 在 GitHub 上创建公开仓库 reports-site（仓库名需匹配 astro.config.mjs 里的 base）。
  2. 本地：
    git remote add origin git@github.com:TerenceXie/reports-site.git
git branch -M main
git push -u origin main
  3. 到仓库 Settings → Pages，Source 选 GitHub Actions。
  4. 之后每次 pnpm deploy 即自动构建发布，地址：
    https://terencexie.github.io/reports-site/

常见问题

列表里看不到我刚加的 HTML？

预构建钩子只在 pnpm dev 启动时跑一次。新增/修改文件后重启 pnpm dev，或运行 pnpm prebuild 后刷新页面。

我的 HTML 里有 fixed 定位的元素，被「返回列表」按钮挡住？

按钮的 z-index 是最大值，确实会盖住。如果某篇文章不希望被注入，可以在 scripts/build-posts.ts 的 injectBackButton 里加判定（例如检测 <meta name="no-back-button"> 跳过）。

需要换仓库名或加自定义域名？

  • 换名：修改 astro.config.mjs 的 base，以及 scripts/build-posts.ts 顶部的 BASE。
  • 自定义域名：在 public/ 下放一个 CNAME 文件，内容写你的域名；同时把 base 改成 "/"。
